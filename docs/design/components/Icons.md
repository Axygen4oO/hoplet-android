## Назначение

Этот документ задает единую систему иконографики Hoplet.  
Иконки должны быть функциональными, технически чистыми и согласованными по толщине, а не декоративными.

---

## Визуальный характер

Иконки Hoplet должны быть:

- геометрически чистыми;
- округло-техническими;
- хорошо читаемыми в маленьком размере;
- без излишней игрушечности;
- без ультратонких линий.

---

## Размеры

| Размер | Использование |
| --- | --- |
| `16 dp` | редкие служебные маркеры |
| `20 dp` | leading/trailing в строках |
| `24 dp` | основной стандарт |
| `32 dp` | крупные статусные маркеры |

---

## Толщина линий

- На `24 dp` использовать оптически около `2 dp`.
- На `20 dp` линия может быть чуть тоньше, но не хрупкой.
- На `32 dp` допустимо небольшое усиление толщины.

---

## Filled и Outlined

| Режим | Когда использовать |
| --- | --- |
| `Outlined` | нейтральные состояния, невыбранная нижняя навигация, спокойные secondary-actions |
| `Filled` | active-state, status-accent, выраженный primary-state |

---

## Правила применения

- На одном экране использовать один и тот же иконографический язык.
- Иконка не заменяет label там, где label нужен по смыслу.
- Критическое или деструктивное действие нельзя делать понятным только по иконке без текста или label.
- Иконки в navigation и status-components должны поддерживать иерархию, а не спорить с ней.

---

## Запреты

- Смешивать разные наборы иконок на одном экране.
- Использовать iOS-подобные ультратонкие glyph-иконки.
- Подменять системные роли случайными иллюстративными символами.

---

## Проверка перед использованием

1. Иконка читается в своем размере без напряжения?
2. Ее стиль совпадает с остальными иконками экрана?
3. Пользователь поймет действие или статус даже при плохом различении цвета?
4. Иконка действительно помогает, а не дублирует шум?
