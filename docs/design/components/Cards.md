# Cards

Источник правил: [HOPLET_LIQUID_GLASS.md](../../../HOPLET_LIQUID_GLASS.md), разделы 4, 5, 6, 13, 14, 15, 16, 17  
Справочники: [Layout.md](Layout.md), [Typography.md](Typography.md), [Icons.md](Icons.md)

---

## Группа

Карточки в Hoplet используют один базовый язык: `Surface` по умолчанию, радиус `28 dp`, тонкая граница, короткая мягкая тень и спокойная иерархия контента.  
Разные card-role меняют содержание и акцент, но не меняют геометрию без объективной причины.

---

## Компоненты группы

| Компонент | Роль |
| --- | --- |
| `GlassCard` | короткий управляющий glass-контейнер |
| `StatusCard` | главный статусный блок экрана |
| `InfoCard` | информационный блок без выбора |
| `SettingsCard` | контейнер для параметров и grouped settings |
| `StatisticsCard` | карточка с метриками и числами |
| `ConnectionCard` | карточка состояния подключения и действий |
| `ServerCard` | карточка сервера/узла |
| `DeviceCard` | карточка устройства |
| `SubscriptionCard` | карточка подписки |
| `ConnectionProgressCard` | пошаговый прогресс подключения |

---

## Общие ограничения группы

- Геометрия обычной карточки наследуется из раздела `6.1. Базовая карточка Hoplet`.
- Glass для карточек допустим только там, где карточка фактически является коротким управляющим слоем, а не длинным контентным блоком.
- Длинный текст, формы, плотные списки и логи не должны жить внутри glass-карточек.

### GlassCard

**Назначение**  
Компактный приподнятый управляющий блок для быстрых действий, поиска, фильтров или короткой tool-панели.

**Где используется**  
Верхние управляющие контейнеры, quick actions, компактные filter/search-блоки, floating control-panels.

**Когда использовать**  
Когда нужен визуально отделенный control-layer с небольшим количеством контента и быстрыми действиями.

**Когда НЕ использовать**  
Для длинных текстов, форм из нескольких полей, логов, таблиц, плотных списков и любых heavy-content блоков.

**Внешний вид**  
Материал: `Glass`.  
Цвет и контур: `Glass Fill` + `Glass Stroke`.  
Радиус и отступы: по [Layout.md](Layout.md), с геометрией на уровне основной карточки или компактного control-shell.  
Типографика: короткие `Title` и `Label`, без длинних `Body` блоков.  
Иконки: спокойные, `20-24 dp`, по [Icons.md](Icons.md).  
Анимации: тихое press-feedback и мягкое появление, по разделу 15 исходного стандарта.

**Состояния**  
Normal, Pressed, Focused, Disabled.  
Loading, Success и Error применимы только если GlassCard содержит action или статус.

**Поведение**  
Должен реагировать быстро и тихо, не меняя размер. Если стекло ухудшает читаемость или производительность, заменяется на имитированный glass.

**Accessibility**  
Контраст текста обязателен. Интерактивные зоны не меньше `48 x 48 dp`. Стекло не должно скрывать статус или лейбл.

**Что разрешено изменять**  
Иконку, текст, ведущий/замыкающий action, акцент активного состояния.

**Что запрещено изменять**  
Идею short-control-layer, правила glass, радиусную систему, поведение blur, стиль глубины.

**Примеры использования**  
Плавающий блок фильтров, компактная search-shell, quick action panel.

### StatusCard

**Назначение**  
Главный статусный блок экрана, который отвечает на вопрос "что происходит сейчас".

**Где используется**  
Главный статусный экран, экран подключения, верхняя секция логов, важные экранные summaries.

**Когда использовать**  
Когда нужно показать текущее состояние системы и рядом разместить одно главное действие или ключевые метрики.

**Когда НЕ использовать**  
Для вторичных справок, плотных настроек или длинных описаний.

**Внешний вид**  
Материал: `Surface`.  
Акцент: умеренный, через статус, иконку, border или leading-marker, а не полной заливкой.  
Радиус: основная карточка Hoplet.  
Типографика: один `Title`, один `Body`/`Caption`, при необходимости `Status` для inline-state.  
Иконки: `24-32 dp` для выраженного статуса.  
Анимации: плавная смена статуса без скачков layout.

**Состояния**  
Normal, Pressed при кликабельности, Loading, Success, Error, Disabled при недоступности действия.

**Поведение**  
Главное действие должно быть очевидным. Смена состояния не должна ломать композицию карточки.

**Accessibility**  
Статус поддерживается цветом, текстом и иконкой одновременно. Критические статусы не передаются только цветом.

**Что разрешено изменять**  
Текст статуса, secondary explanation, одну статусную иконку, один primary action.

**Что запрещено изменять**  
Радиусы, карточный язык, превращение в glass-фон, многослойные декоративные тени.

**Примеры использования**  
Карточка "Подключено / Подключение / Ошибка", карточка текущего состояния туннеля.

---

### InfoCard

**Назначение**  
Нейтральный информационный блок без доминирующего действия.

**Где используется**  
Информационный экран, onboarding, подсказки, поясняющие секции настроек.

**Когда использовать**  
Когда нужно объяснить состояние, правило или контекст без превращения блока в alert или primary action.

**Когда НЕ использовать**  
Для destructive-решений, длинных логов и управляющих панелей.

**Внешний вид**  
Материал: `Surface` или `Surface Soft` при вторичном акценте.  
Типографика: `Title` + `Body`/`Caption`.  
Иконка: optional, `20-24 dp`.  
Акцент: минимальный, без крикливого фона.  
Отступы и радиусы: по базовой карточке.

**Состояния**  
Normal.  
Pressed только если вся карточка открывает детали.  
Loading, Success, Error обычно не применяются.

**Поведение**  
Может быть статичной или открывать подробности. Не должна конкурировать с primary action экрана.

**Accessibility**  
Текст должен быть читаемым в `Body`, а не в уменьшенных декоративных стилях.

**Что разрешено изменять**  
Иконку, текст, trailing chevron или secondary action.

**Что запрещено изменять**  
Сделать её hero-блоком, glass-card или предупреждением без явной причины.

**Примеры использования**  
Карточка объяснения режима, блок с короткой инструкцией, описание раздела.

---

### SettingsCard

**Назначение**  
Контейнер секции настроек, объединяющий строки, тумблеры и значения.

**Где используется**  
Экран настроек, экран формы, расширенные параметры.

**Когда использовать**  
Когда несколько связанных параметров нужно держать как один смысловой блок.

**Когда НЕ использовать**  
Для одного-единственного action, логов и полноэкранных форм без секционирования.

**Внешний вид**  
Материал: `Surface` или `Surface Soft`.  
Типографика: short section-title и utility-text.  
Внутри применяются [Lists.md](Lists.md) элементы или поля из [Inputs.md](Inputs.md).  
Glass не используется как базовый материал.

**Состояния**  
Normal, Disabled, Loading, Error при локальной проблеме секции.

**Поведение**  
Секция должна быть стабильной по высоте и визуально выравнивать переключатели, значения и подписи.

**Accessibility**  
Каждый вложенный control должен иметь собственную активную зону и подпись.

**Что разрешено изменять**  
Заголовок секции, состав строк, локальную подсказку, inline warning.

**Что запрещено изменять**  
Размывать иерархию, смешивать несвязанные параметры, переносить glass внутрь форм.

**Примеры использования**  
Группа DNS-настроек, секция параметров подключения, блок app-settings.

---

### StatisticsCard

**Назначение**  
Карточка с ключевыми числовыми показателями и короткими подписями.

**Где используется**  
Главный статусный экран, профиль, состояние подписки, сетевые summaries.

**Когда использовать**  
Когда важны сравнимые значения: трафик, uptime, активные соединения, версии, лимиты.

**Когда НЕ использовать**  
Если данные длинные, логовые или требуют таблицы.

**Внешний вид**  
Материал: `Surface`.  
Типографика: значение в `Headline`/`Title`, подпись в `Caption` или `Status`.  
Числа должны быть легко сравнимы взглядом; при необходимости используются tabular digits.  
Визуальный акцент строится на ритме и контрасте, не на тяжелом фоне.

**Состояния**  
Normal, Loading, Error.  
Pressed только если карточка раскрывает детали.

**Поведение**  
Показатели не должны прыгать по layout при обновлении. Изменение значения анимируется мягко.

**Accessibility**  
Не передавать смысл только цветом роста/падения. Подписи обязательны.

**Что разрешено изменять**  
Количество метрик, единицы измерения, вторичный акцент.

**Что запрещено изменять**  
Делать из метрик декоративные hero-сцены, дробить на случайные размеры текста.

**Примеры использования**  
Трафик за сессию, uptime, число активных соединений.

---

### ConnectionCard

**Назначение**  
Карточка, объединяющая статус подключения, контекст и доступные действия.

**Где используется**  
Главный статусный экран, экран логов рядом со статусом подключения, список профилей при подключении.

**Когда использовать**  
Когда нужно одновременно показать состояние туннеля и действия пользователя.

**Когда НЕ использовать**  
Для вторичной справки или как замену full progress-сценарию.

**Внешний вид**  
Наследует `StatusCard`.  
Акцент допускается через `Accent Primary`, `Success`, `Error` или `Warning` только локально.  
Допустим один action-cluster, но без перегруженного toolbar внутри карточки.

**Состояния**  
Normal, Loading, Success, Error, Disabled.

**Поведение**  
Должна ясно объяснять, идет подключение, подключено ли уже, есть ли ошибка и что делать дальше.

**Accessibility**  
Статус подключения поддерживается текстом, иконкой и формой. Кнопки внутри не должны сливаться со статусом.

**Что разрешено изменять**  
Статусную иконку, текст, одно primary action и максимум одно secondary action.

**Что запрещено изменять**  
Смешивать внутри несколько равноправных primary action, скрывать ошибку в декоративном оформлении.

**Примеры использования**  
Блок "Подключиться / Остановить", summary текущего подключения.

---

### ServerCard

**Назначение**  
Карточка отдельного сервера или профиля узла.

**Где используется**  
Экран списка профилей, экран выбора сервера, экран подписки.

**Когда использовать**  
Когда сервер является самостоятельным объектом выбора или просмотра.

**Когда НЕ использовать**  
Для dense-таблиц, если серверов слишком много и нужен flat utility list.

**Внешний вид**  
Материал: `Surface`.  
Содержимое: имя, вторичная техинформация, статус, допустимые inline-actions.  
Типографика: `Title` + `Body Dense`/`Caption`.  
Иконки: `20-24 dp`, аккуратные, без перегруженного набора.

**Состояния**  
Normal, Pressed, Selected, Disabled, Loading, Error.

**Поведение**  
Вся карточка кликабельна, если выбор относится ко всему серверу. Secondary-action визуально отделяется.

**Accessibility**  
Выбранность должна читаться по border/marker и тексту, а не только по цвету.

**Что разрешено изменять**  
Название, местоположение, latency/status badge, trailing actions.

**Что запрещено изменять**  
Менять базовый карточный язык, превращать server-card в плотную таблицу на glass.

**Примеры использования**  
Карточка VPN-профиля, карточка сервера внутри группы подписки.

---

### DeviceCard

**Назначение**  
Карточка устройства или клиентского endpoint.

**Где используется**  
Личный кабинет, экран подписки, экран информации об устройстве.

**Когда использовать**  
Когда устройство нужно показать как отдельный управляемый объект.

**Когда НЕ использовать**  
Если нужен компактный список без карточной глубины.

**Внешний вид**  
Наследует `InfoCard` или `StatusCard` в зависимости от критичности.  
Может содержать device-name, platform, status, last activity, limits.

**Состояния**  
Normal, Pressed, Selected, Disabled, Error.

**Поведение**  
Может открывать детали, удаление или переименование должно быть вторичным действием.

**Accessibility**  
Иконка устройства не заменяет текстовое название платформы или статуса.

**Что разрешено изменять**  
Название, платформенную иконку, secondary metadata, status tag.

**Что запрещено изменять**  
Скрывать destructive action среди primary state, перегружать карточку множеством кнопок.

**Примеры использования**  
Устройство пользователя, зарегистрированный клиент, активный endpoint.

---

### SubscriptionCard

**Назначение**  
Карточка подписки с описанием, лимитом, синхронизацией и действиями обновления.

**Где используется**  
Экран профилей, экран подписок, onboarding к подписке Hoplet.

**Когда использовать**  
Когда подписка является самостоятельным объектом и ей нужны статус, метрики и локальные actions.

**Когда НЕ использовать**  
Для простого текстового упоминания подписки без действий.

**Внешний вид**  
Материал: `Surface` или `Surface Soft`.  
Внутри допускаются short metric-lines, progress и compact actions.  
Стили метрик и индикаторов берутся из [Indicators.md](Indicators.md).

**Состояния**  
Normal, Pressed, Loading, Success, Error, Disabled.

**Поведение**  
Обновление и удаление должны оставаться вторичными относительно чтения статуса подписки.

**Accessibility**  
Лимит, трафик и ошибки должны быть выражены текстом, а не только полосой прогресса или цветом.

**Что разрешено изменять**  
Название, описание, метрики, inline progress, action set.

**Что запрещено изменять**  
Разрывать подписку на несколько визуально несвязанных карточек без причины.

**Примеры использования**  
Карточка JSON-подписки, карточка подписки Hoplet, блок синхронизации профилей.

### ConnectionProgressCard

**Назначение**  
Пошаговая визуализация процесса подключения со stage-by-stage статусом.

**Где используется**  
Экран логов, главный статусный экран при соединении, диагностические сценарии.

**Когда использовать**  
Когда важно показать последовательность этапов подключения, а не только итоговый статус.

**Когда НЕ использовать**  
Для обычной короткой загрузки, где хватает `LoadingIndicator` или локального `ProgressIndicator`.

**Внешний вид**  
Материал: `Surface`.  
Акцент: локальные status-colors на узлах и соединителях, без неоновых эффектов.  
Типографика: краткие подписи стадий и один общий статус.  
Анимации: спокойный progress-motion, success/error подтверждаются цветом, иконкой и мягким motion shift.

**Состояния**  
Normal, Loading, Success, Error.  
Pressed и Disabled обычно не применяются.

**Поведение**  
Контейнер раскрывается и обновляется плавно. Структура шагов остается стабильной даже при смене статуса.

**Accessibility**  
Каждый этап должен иметь название и статус. Пользователь не должен читать состояние только по цвету узла.

**Что разрешено изменять**  
Названия этапов, summary metrics, локальный success/error marker.

**Что запрещено изменять**  
Превращать прогресс в шоу-анимацию, использовать мигающие сигналы или сильное свечение.

**Примеры использования**  
Диагностика "подготовка - соединение - проверка - готово", пошаговый прогресс VPN.
